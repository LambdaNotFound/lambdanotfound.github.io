# CLAUDE.md

Personal GitHub Pages site. The root `index.html` is a placeholder. The real content is the Daily Practice page in `practice/` (Vite, React 19, TypeScript, plain CSS, Vitest), served at https://lambdanotfound.github.io/practice/. It has two tabs on a rail at the left: Coding (`#coding`, the daily plan) and Design (`#design`, `#design/<slug>`, the system designs). See [README.md](README.md) for the data flow and the dev commands.

## Rules for the page

- **No "leetcode" in anything a viewer sees.** That covers the page text, `<title>`, button labels, and the title and body of the log issue the page opens. Links may point at leetcode.com, but the word must not appear as visible text. The browser check below tests `document.title` plus `document.body.innerText` against `/leetcode/i`. Some solution comments in GoCode name the site, so code snippets go through `maskSiteName` before they are shown.
- **The look is settled.** Build on the tokens, light and dark themes and layout in `practice/src/styles.css`, and don't restyle the page.
- **No backend.** The page reads `spaced_repetition/state.json`, `problems.json` and `README.md` from GoCode's `main` at runtime, plus, when "Show code" is pressed, the solution file the README links for that problem, and logs by commenting on the plan's "Daily Practice YYYY-MM-DD" issue, which GoCode's `log-solve.yml` accepts. The page finds that issue by its exact title in the 30 newest issues (`findDailyIssue`), so it depends on `daily-leetcode.yml`'s title. GitHub can't prefill a comment: "Log on GitHub" copies the lines inside the click, before the new tab takes focus, and opens the issue. With a token the viewer saved (localStorage, never sent anywhere but api.github.com), "Log now" posts the comment through the API instead, as the token's owner, which is what `log-solve.yml` checks. When the issue can't be found, both fall back to a "Practice log YYYY-MM-DD" issue, prefilled or created. The types in `practice/src/lib/practice.ts` mirror GoCode's files: when either side changes shape, change the other in the same piece of work.
- **Code snippets.** `src/lib/snippet.ts` starts at the comment holding the README link's `#L` line and runs to the next block comment or docstring at that comment's indentation, a `// N. Title` line comment, or less-indented code; a link to line 1 shows the whole file. So it depends on GoCode's header comments, and GoCode's `CLAUDE.md` says so. `src/lib/highlight.ts` is shiki's fine-grained core with the JavaScript regex engine (no WebAssembly), imported only when a panel first opens, and each grammar loads on first use. Its two themes put every token color at 4.9:1 or better on `--sheet` in light and 5.4:1 in dark; check that again before swapping either.
- **Tabs.** `App.tsx` routes on the hash. Both tabs stay mounted once opened, and the one not showing is laid out off screen (`.view.off`), so switching keeps grades, open panels and each tab's scroll position. The incoming tab fades in, and one highlight slides between the two tab links. The user asked for this after an earlier version flickered on every switch, so keep switches free of layout jumps: every view opens with the same `.crumb` line above its title, and `scrollbar-gutter: stable` keeps the width fixed.
- **Designs are copied in at build time.** The deploy checks out the public `LambdaNotFound/system-design` repository into `practice/designs-src/` (git-ignored), and `src/lib/designs.ts` bundles every `design-doc/<slug>/rfc.md` there with `import.meta.glob`, in a chunk that loads only when the Design tab opens. `src/lib/rfc.ts` sorts each RFC into the eight steps the Design page shows: functional and non-functional requirements, core entities, API, data flow, the architecture diagram (the Overview's drawing, taken out of its prose by `splitArchitecture`), high-level design, and low-level design with the deep dives. It relies on the shape system-design's `.claude/skills/new-design/rfc-spec.md` fixes, and system-design's `CLAUDE.md` says so: when either side changes, change the other in the same piece of work. The page never grades the RFC's options good or bad, since the RFC doesn't; it shows the `**Chosen:**` line and what was rejected.
- **Diagrams.** The RFCs' Mermaid blocks draw in the browser (`src/lib/mermaid.ts`). Mermaid is not an npm dependency: it loads from jsDelivr, pinned to an exact version, the first time a design opens. Diagrams sit on a light plate (`--plate`) in both themes, because the RFCs set their own light colors.
- Dependencies are pinned to exact versions, so add new ones with an exact version too. They were installed with `npm install --before=<date>`, which skips releases newer than that date.

## Deploying

`.github/workflows/deploy.yml` tests, builds and publishes on every push to `main`, daily at 13:17 UTC so new designs arrive, and from "Run workflow". That only works while Settings > Pages > Source is "GitHub Actions". If the page goes blank and https://lambdanotfound.github.io/practice/package.json loads, the setting is back on "Deploy from a branch", which publishes the raw source. A run named "pages build and deployment" in the Actions tab gives the same sign. After a push, check the live page before reporting it as working.

## Testing

- `cd practice && npm test` runs the pure logic in `src/lib/`. `npm run build` type-checks too.
- For a change to the UI, build with `VITE_DATA_BASE` pointing at fixture copies of the three data files. Then drive it in a headless browser at 1280 px and 390 px, light and dark. Check that nothing scrolls sideways at 390 px, the word rule holds, and the log link's title and body come out right. Block requests to api.github.com so a test never posts anything: answer the issue list with a fake "Daily Practice <plan date>" issue (and once with none, for the fallback), and the POST with a fake comment to check "Log now". Grant clipboard access and read it back to check what "Log on GitHub" copied. For "Show code", serve GoCode's working tree as the data: the panel must not exist, and no solution file or shiki chunk may load, before the first click. For the Design tab, put a clone of system-design (or a symlink to one) at `practice/designs-src/`; then check that switching tabs keeps each tab's scroll position, that every Mermaid block draws, and that the word rule holds on the design page too.

## Commits

Same format as GoCode: `MM-DD-YYYY: <short description>`, at most 72 characters, local date. No hook enforces it here.
